# Временное сопоставление подразделений с публичных страниц tou.edu.kz

Инструментарий временного обхода, пока офис регистратора не ответил на запрос
D2 (docs/REQUESTS.md): реальные выгрузки `stats/` несут только ФИО и e-mail
проверяющего, поэтому справочники и сопоставление «проверяющий → кафедра»
строятся из общедоступной структуры сайта университета и совмещаются с
выгрузками по ФИО. Подробности применения - deploy/RUNBOOK.md, раздел
«Временный обход».

Порядок (запуск из корня репозитория, нужен Python 3.11+):

```bash
python scripts/real-units/scrape.py     # структура сайта -> stats/real-units-work/
python scripts/real-units/match.py      # ФИО-сопоставление -> stats/real-staff-units.csv
python scripts/real-units/build_sql.py  # SQL с HMAC (пеппер из deploy/.env)
```

Все рабочие файлы и результаты пишутся под `stats/` (в `.gitignore`):
сырые адреса никогда не попадают ни в Git, ни в базу - в
`stats/real-staff-units.sql` уходят только HMAC-дайджесты и маскированные
метки (ADR-008 §2). `stats/real-work-type-rules.sql` (расширение правил типов
работ под реальные названия) написан вручную и обновляется правкой на месте.

Официальный ответ D2 должен заменить этот скрейп через админ-редактор
справочников; скрипты тогда остаются только как история происхождения данных.
