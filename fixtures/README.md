# Фикстуры - детерминированные данные для проверки

Срез **W0.3**. Всё здесь синтетическое и порождено от зерна: одно и то же зерно
всегда даёт одни и те же байты, поэтому «числа совпадают» - машинно проверяемое
утверждение, а не вопрос суждения (ARCHITECTURE §9, AGENTS.md §6).

Генератор выдаёт CSV **в форме источника** - реальный диалект выгрузки legacy-вендора,
зафиксированный в [ADR-008](../docs/adr/008-legacy-derivation-and-hmac.md) §1,
вместе с некорректными строками, - так что Rust-импортёр проверяется на своём
настоящем входе, а не на удобном.

> `stats/` в корне репозитория содержит РЕАЛЬНЫЕ исходные выгрузки с
> персональными данными. Их нельзя копировать сюда, коммитить или загружать
> необезличенными - инвариант #1 из AGENTS.md. Ничто в этом каталоге из них не
> выведено; диалект взят из ADR-008, а не из файлов.

## Команды

```bash
bun fixtures/generate.ts --scale small     # ~60 тыс. проверок / 3 учебных года (по умолчанию)
bun fixtures/generate.ts --scale load      # ~250 тыс. проверок / 5 учебных лет
bun fixtures/expected.ts                   # редьюсер → expected.json + out/facts.jsonl
bun fixtures/verify.ts                     # шлюз детерминизма (CI)
bun fixtures/seed.ts                       # загрузка в локальный Postgres
```

Флаги: `--seed N` (по умолчанию `1`), `--root DIR` (по умолчанию `fixtures`).
`seed.ts` принимает также `--force` (перегенерировать), `--reset` (сбросить схему через
`reset.sql`, повторно применить миграции, затем засеять) и `--skip-ingest`.

Окружение для `seed.ts`:

| Переменная          | По умолчанию                                              | Примечания                                                       |
| ------------------- | --------------------------------------------------------- | ---------------------------------------------------------------- |
| `APP_DATABASE_URL`  | `postgres://noplagiat:noplagiat@localhost:5432/noplagiat` |                                                                  |
| `APP_INGEST_PEPPER` | `dev-pepper` (с предупреждением)                          | ADR-008 §2 - только в окружении, никогда в Git, в БД или в логах |

**Перегенерируйте всё вместе.** Изменение `generate.ts` или `rules.ts`
инвалидирует `out/`, артефакты SQL/CSV, `expected.json` **и**
`out/facts.jsonl`; запустите `generate.ts`, затем `expected.ts` и укажите это в
теле коммита. `expected.ts` пишет оба своих выхода за один проход - это две
проекции одной редукции, и их нельзя порождать по отдельности. Никогда не
правьте `expected.json`, чтобы тест прошёл, - пересчитайте его и разберитесь с
расхождением.

## Файлы

| Путь                        | Генерируется? | Что это                                                                         |
| --------------------------- | ------------- | ------------------------------------------------------------------------------- |

| `generate.ts`               | исходник      | генератор от зерна (mulberry32)                                                 |
| `expected.ts`               | исходник      | независимый редьюсер полным перебором                                           |
| `verify.ts`                 | исходник      | шлюз детерминизма                                                               |
| `seed.ts`                   | исходник      | оркестратор локального засева                                                   |
| `reset.sql`                 | исходник      | сброс схемы (принадлежит линии db)                                              |
| `out/<ay>/documents.csv`    | **да**        | строки фактов в форме источника                                                 |
| `out/<ay>/system-usage.csv` | **да**        | однострочный агрегат → `source_control_totals`                                  |
| `out/<ay>/malformed.json`   | **да**        | точные ожидаемые количества отклонений + индексы строк                          |
| `out/manifest.json`         | **да**        | зерно, масштаб, итоги по годам                                                  |
| `out/facts.jsonl`           | **да**        | заранее выведенные строки хранилища для линии db (пишет `expected.ts`)          |

| `work-type-rules.sql`       | **да**        | шаблон названия → вид работы (ADR-008 §7)                                       |
| `initiator-rules.sql`       | **да**        | e-mail проверяющего → роль инициатора (ADR-008 §5)                              |
| `staff-units.csv`           | **да**        | e-mail проверяющего → `faculty_code;department_code`                            |
| `expected.json`             | **да**        | эталонные агрегаты: сырые (внутренний контур) **и** публичное замыкание ADR-016 |

Весь SQL использует `ON CONFLICT (code) DO NOTHING` либо охрану `NOT EXISTS` и
разрешает идентификаторы **по коду** (никогда не жёстко зашитые), поэтому он
идемпотентен и сочетается со вставками сентинелов `UNASSIGNED` / `other` из
миграции 0002 в любом порядке.

`out/` большой (~57 МБ при `small`, включая `facts.jsonl`, ~235 МБ при `load`)
и полностью воспроизводим из зерна - **рекомендуется внести в `.gitignore`**, что
покрывает и `facts.jsonl`. `expected.json` (~90 КБ) коммитится: это контракт,
относительно которого утверждают линии db, reports и e2e.

## Диалект CSV (ADR-008 §1)

- UTF-8 **с BOM**, разделитель `;`, кавычки по RFC-4180, десятичная **запятая**,
  даты `dd.MM.yyyy HH:mm`.
- Записи разделяются **CRLF**; перевод строки **внутри** закавыченного поля - это
  одиночный **LF**, поэтому эти два случая никогда не смешиваются.
- Ровно 14 колонок, в порядке из ADR. Любое несовпадение заголовка отклоняет всю
  партию.
- Булевы значения: «Да» → true, всё остальное → false.
- `source_check_id = "{userId}:{reportId}"`, разбирается из ссылки на отчёт.

### Дефекты качества данных, которые фикстура содержит намеренно (PLAN §1.4)

| Форма                                                   | За год                     | Импортёр обязан                       |
| ------------------------------------------------------- | -------------------------- | ------------------------------------- |
| закавыченные поля, содержащие `;` (соавторы, названия)  | ~1 900–2 100               | **разобрать** - эти строки корректны  |
| закавыченные поля со встроенным переводом строки        | 82–116                     | **разобрать** - эти строки корректны  |
| закавыченные поля с экранированными `""`                | 38–46                      | **разобрать** - эти строки корректны  |
| строки «Удален»                                         | 0.8–5 %                    | исключить из фактов, считать отдельно |
| дублирующиеся ссылки на отчёт (попытки с общей ссылкой) | ~2 % перепроверенных работ | выполнить идемпотентный upsert        |
| строки со сдвигом колонок (URL отчёта в «Статус»)       | 2–5                        | **отклонить**, никогда не угадывать   |
| неудалённая строка с неразбираемой ссылкой на отчёт     | 2                          | **отклонить**, никогда не угадывать   |

`out/<ay>/malformed.json` несёт точные количества и **логические** индексы
записей, отсчитываемые от 0 (заголовок исключён; запись может занимать несколько
физических строк),
поэтому тесты импорта утверждают точные количества отклонений, а не «сколько-то».

### `system-usage.csv`

«Совершенных проверок» - это число строк, которые **корректный импортёр
принимает** за этот год: неудалённых _и_ корректно оформленных, то есть
`rows_total − rows_deleted − rows_rejected_expected` из сопутствующего файла.
Поэтому сверка (W4.3) на чистом импорте должна давать нулевое расхождение.

## Инварианты фикстур, на которые могут опираться другие линии

1. **Удалённые и некорректные строки - самостоятельные работы** (уникальные
   названия). Поэтому нумерация попыток не может зависеть от того, отфильтрованы
   ли они до или после группировки, - импорт и этот редьюсер не могут разойтись
   на законных основаниях.
2. **Каждый `work_ref` живёт внутри одного учебного года**, поэтому погодовые
   партии импорта никогда не разрезают лестницу попыток одной работы.
3. **Привязка к подразделению - это ровно членство в `staff_units`** (ADR-008 §6):
   проверяющий, присутствующий в карте, получает свои факультет и кафедру, все
   остальные попадают на оба сентинела `UNASSIGNED`. Поскольку карта ключуется по
   проверяющему, а не по году, и небольшая часть служебных e-mail 2025/26 уч. г.
   встречается также в более раннем пуле проверяющих, годы до 2025/26 являются
   **преимущественно**, а не **полностью** непривязанными. При `--scale small`,
   зерно 1:

   | Учебный год | фактов | привязано | не привязано |
   | ----------- | ------ | --------- | ------------ |
   | 2023/24     | 19 200 | 317       | 98.3 %       |
   | 2024/25     | 20 000 | 0         | 100 %        |
   | 2025/26     | 20 800 | 18 350    | 11.8 %       |

   Поэтому фильтр по факультету на полном диапазоне доминируется 2025/26, но не
   исчерпывается им - такова реальность PLAN §1.2 и сноски в интерфейсе, и
   поэтому шлюз импорта утверждает `unassigned_share > 0.9` для раннего года, а
   не `== 1.0` (`ingest::golden_parse::unit_attribution_is_exactly_staff_unit_membership`).
   Не пишите тест, предполагающий, что агрегат до 2025/26 пуст.

4. **FAC08 зарезервирован под искусственно созданные малые группы.** Его ячейки
   «факультет × вид работы × месяц» содержат ровно 1, 2, 3, 4, 5 и 6 строк -
   `n = 1..k+1` при k = 5, - так что и первичному, _и_ комплементарному
   подавлению есть за что зацепиться.
5. **Точные границы корзин присутствуют:** 50.00, 70.00, 85.00 и 95.00 встречаются
   примерно по 20 раз за учебный год в колонке оригинальности.
6. **Отметки времени наивные и интерпретируются в +05:00** для всех лет.
   Разбиение по месяцам, семестрам и учебным годам происходит по этой местной
   гражданской дате. Поэтому SQL должен усекать в `Asia/Almaty` (или в
   эквивалентном фиксированном +05:00), а не в UTC. Это обеспечено конструктивно:
   около 478 строк приходятся на промежуток между 00:00 и 05:00 **1-го числа
   месяца**, поэтому запрос, усекающий в UTC, относит их к предыдущему месяцу, и
   агрегат расходится с `expected.json`.
7. **`program_id` никогда не заполняется.** ОП не выводится из legacy-выгрузки
   (PLAN §1.1); словарь программ существует, чтобы поверхность фильтров была
   непустой, и фильтр по программе всегда даёт пустое множество.
8. **`staff-units.csv` стабилен между масштабами.** Пулы проверяющих порождаются
   только из учебного года, поэтому `small` и `load` сходятся в том, кто
   существует.

## Контракт `expected.json`

Каждый сценарий несёт **две** редукции одних и тех же фактов:

- блоки верхнего уровня `summary` / `timeseries` / `work_types` / `units` / `histogram`
  / `yoy` / `rechecks` / `escalations` / `usage` - это **сырые**,
  **до k-анонимности** агрегаты, то есть то, что публикует _внутренний_ контур.
  Подавление проверяется отдельно линией `compliance` относительно этих
  чисел (ADR-008 §10), поэтому здесь ничто не подавлено и группы размером меньше k
  видны намеренно;
- блоки `public_*` - это **публичное замыкание релиза** из ADR-016, то есть то,
  что публикует _публичный_ контур. Они вычисляются второй раз, независимо
  (`publicView()` в `expected.ts` не разделяет ни строки с `reduceScenario()`).

Эти две редукции различаются ровно на изъятые ячейки и на окно: блок `public_*`
вычисляется по `public_filters`, то есть по диапазону сценария, **выровненному до
целых месяцев**, с отброшенными `status`, `department` и `program` - они не
являются публичными измерениями (ADR-016 §1, §3). Поэтому у
`custom-range-crossing-month` публичный итог _больше_ сырого (1 октября – 30 ноября
против 15 октября – 14 ноября), а у `all-time-no-filter` - меньше (59 771
опубликовано из 60 000 при изъятии 92 ячеек).

### Блоки `public_*`

```json
{
  "public_filters": {
    "from": "YYYY-MM-01",
    "to": "YYYY-MM-DD",
    "faculty": null,
    "work_type": null
  },
  "public_summary": {
    "checks": 0,
    "avg_originality": 0.0,
    "below_threshold": 0,
    "below_threshold_share": 0.0,
    "escalated": 0,
    "suppressed_groups": 0
  },
  "public_timeseries": [
    { "month": "YYYY-MM-01", "checks": 0, "avg_originality": 0.0 }
  ],
  "public_work_types": [{ "code": "…", "checks": 0, "avg_originality": 0.0 }],
  "public_faculties": [{ "code": "…", "checks": 0, "avg_originality": 0.0 }],
  "public_histogram": {
    "lt50": 0,
    "b50_70": 0,
    "b70_85": 0,
    "b85_95": 0,
    "ge95": 0,
    "total": 0
  },
  "public_yoy": [{ "academic_year": 2023, "checks": 0, "avg_originality": 0.0 }]
}
```

- Каждый показатель - это сумма по ячейкам куба `(month, faculty, work type)`,
  содержащим не менее `k = 5` проверок. Ячейка ниже `k` не вносит вклада **ни
  во что** - ни в строку, ни в итог, ни в полосу.
- Строка с `"checks": 0` не имела **ни одной опубликованной ячейки**: API
  публикует для неё `"insufficient_data"`, и строка всё равно перечисляется, чтобы
  «недостаточно данных» показывалось явно (TZ §8). Ни одна группа с опубликованной
  ячейкой не может иметь `checks < k`, поэтому `checks == 0` - это ровно случай
  изъятия.
- `suppressed_groups` - число ячеек куба, изъятых при этом фильтре; оно одинаково
  во всех представлениях, что и проверяет `verify.ts`.
- `avg_originality` и `below_threshold_share` округляются **один раз**, по правилу
  «половина вверх» до 4 знаков после запятой, в целочисленной арифметике
  (`ratio4`) - то же правило применяет `api::dto::ratio4`, поэтому итог и строки,
  которые в него суммируются, совпадают до последней цифры.
- Каждая свёртка разбивает одни и те же опубликованные ячейки, поэтому
  `Σ public_faculties = Σ public_work_types = Σ public_timeseries =
Σ public_yoy = Σ полос public_histogram = public_summary.checks`. Это и есть
  свойство замыкания, и `verify.ts` утверждает все пять равенств.

`avg_originality` - среднее, округлённое по правилу **«половина вверх» до 4
знаков**, вычисленное в целых сотых, так что оно никогда не зависит от порядка
ассоциации при сложении чисел с плавающей точкой; `below_threshold_share`
округляется так же. Пустые группы опускаются, а не выдаются с нулями. Порядок
ключей зафиксирован; массивы отсортированы детерминированно
(`timeseries`/`usage` по месяцу, `work_types` по коду, `units` по факультету, затем
по кафедре, `yoy` по учебному году).

```json
{
  "meta": {
    "seed": 1,
    "scale": "small",
    "rows_generated": 0,
    "rows_deleted": 0,
    "rows_malformed": 0
  },
  "scenarios": [
    {
      "name": "…",
      "filters": {
        "from": "YYYY-MM-DD",
        "to": "YYYY-MM-DD",
        "faculty": null,
        "department": null,
        "program": null,
        "workType": null,
        "status": null
      },
      "summary": {
        "checks": 0,
        "avg_originality": 0.0,
        "below_threshold": 0,
        "below_threshold_share": 0.0
      },
      "timeseries": [
        { "month": "YYYY-MM-01", "checks": 0, "avg_originality": 0.0 }
      ],
      "work_types": [{ "code": "…", "checks": 0, "avg_originality": 0.0 }],
      "units": [
        {
          "faculty": "…",
          "department": "…",
          "checks": 0,
          "avg_originality": 0.0
        }
      ],
      "histogram": {
        "lt50": 0,
        "b50_70": 0,
        "b70_85": 0,
        "b85_95": 0,
        "ge95": 0
      },
      "yoy": [{ "academic_year": 2023, "checks": 0, "avg_originality": 0.0 }],
      "rechecks": { "works_total": 0, "works_rechecked": 0, "improved": 0 },
      "escalations": { "checks_escalated": 0 },
      "usage": [{ "month": "YYYY-MM-01", "active_reviewers": 0 }]
    }
  ]
}
```

Семантика полей следует ADR-008 §9:

- `meta.rows_generated` - записи данных по всем `documents.csv` (включая удалённые
  и некорректные); `rows_deleted` / `rows_malformed` - исключённые и отклонённые
  подмножества. Факты = `rows_generated − rows_deleted − rows_malformed`.
- `summary.below_threshold` - `originality < settings.originality_threshold`
  (по умолчанию 70).
- `histogram` - включая нижнюю границу: `<50, [50,70), [70,85), [85,95), ≥95`.
- `rechecks` - по **отфильтрованным** строкам, сгруппированным по `work_ref`:
  `works_total` = различные работы, `works_rechecked` = работы с ≥ 2 попытками в
  отфильтрованном множестве, `improved` = перепроверенные работы, у которых
  последняя попытка лучше первой.
- `escalations.checks_escalated` - `Подозрительный = Да AND Отметка снята ≠ Да`,
  независимо от лестницы статусов. Счётчики Совета по этике живут в
  `ethics_cases` (вручную, D11) и в этот файл не входят.
- `usage.active_reviewers` - различные `reviewer_ref` за месяц.
  У `avg_check_seconds` нет источника в выгрузке («нет данных»).

## `out/facts.jsonl` - заранее выведенные строки хранилища

Пишется тем же запуском `bun fixtures/expected.ts`, который порождает
`expected.json`. Он существует для того, чтобы `#[sqlx::test]` линии db могли
массово загружать хранилище **без повторной реализации вывода по ADR-008**:
каждая строка уже сгруппирована в попытки, проведена по лестнице статусов,
классифицирована, привязана к подразделению и захеширована HMAC.

Один компактный JSON-объект на строку, **без хвостовых пробелов, с одним
завершающим переводом строки**, отсортировано по `(checked_at, source_check_id)`.
Присутствуют только импортируемые строки - «Удален» и отклонённые исключены,
поэтому число строк в точности равно
`meta.rows_generated − meta.rows_deleted − meta.rows_malformed` (60 000 при
`small`, 250 000 при `load`).

```json
{
  "source_check_id": "<userId>:<reportId>",
  "attempt_no": 1,
  "checked_at": "2023-09-01T00:09:00+05:00",
  "academic_year": 2023,
  "work_type_code": "course",
  "faculty_code": "FAC01",
  "department_code": "DEP01",
  "program_code": null,
  "originality_pct": "81.25",
  "status": "accepted",
  "escalated": false,
  "initiator": "staff_self",
  "suspicious": false,
  "suspicion_cleared": false,
  "self_citation_pct": "1.20",
  "citation_pct": "3.40",
  "match_pct": "14.15",
  "ai_content_pct": null,
  "work_ref": "<64-char lowercase hex>",
  "reviewer_ref": "<64-char lowercase hex>"
}
```

- **Порядок ключей - часть контракта.** `verify.ts` падает, если он смещается.
- `status` ∈ `accepted | needs_revision | rejected | recheck`; `initiator` ∈
  `student | staff_self | registrar | other` - написание перечислений
  `check_status` и `initiator_role` из миграции 0001.
- `escalated` независим от лестницы: это ровно
  `suspicious AND NOT suspicion_cleared` (ADR-008 §4).
- Проценты - **десятичные строки с 2 знаками после запятой**, чтобы они
  проходили полный цикл через `NUMERIC(5,2)` без ошибки плавающей точки; `null`,
  когда исходное поле пустое. `program_code` всегда `null` (ОП не выводится -
  PLAN §1.1). В текущей фикстуре `ai_content_pct` заполнен всегда, поэтому ветка
  `null` в writer-е проверяется формой, а не данными.
- `attempt_no` плотно нумеруется `1..n` внутри каждого `work_ref`, и
  `attempt_no > 1` ⟺ `status = "recheck"`.

### Пеппер равен `dev-pepper`, и это намеренно

`work_ref` и `reviewer_ref` - это HMAC-SHA256 согласно ADR-008 §2:

```
work_ref     = HMAC-SHA256(pepper, "work\n"     ++ norm(title) ++ "\n" ++ norm(authors))
reviewer_ref = HMAC-SHA256(pepper, "reviewer\n" ++ norm(email))
```

Файл поставляется **уже с посчитанными HMAC**, поэтому дайджесты должны быть
воспроизводимы из одного лишь репозитория, а пеппер здесь не может быть секретом.
Он прибит к константе `dev-pepper` (`FIXTURE_PEPPER` в `expected.ts`). Это
корректно только потому, что каждый e-mail, название и автор в фикстуре
синтетические - восстанавливать нечего, и пеппер ничего не защищает.

**Реальный импорт никогда не должен использовать это значение.** Он читает
`APP_INGEST_PEPPER`, который остаётся только в окружении, вне Git, вне базы данных
и вне логов (ADR-008 §2). `fixtures/seed.ts` по умолчанию берёт ту же константу,
когда `APP_INGEST_PEPPER` не задана (и предупреждает об этом), поэтому
`staff_units.email_hmac` соединяется с этими `reviewer_ref` из коробки; экспортируйте
другой пеппер - и эти два перестанут совпадать: засевайте со значением по
умолчанию либо перегенерируйте.

## Независимость

`expected.ts` не содержит SQL и ничего не импортирует из `server/` или `apps/web/`.
Единственная общая с генератором поверхность - `rules.ts`, который содержит _данные_
плюс `norm()`. Разбор CSV, группировка попыток, лестница статусов, корзины и
арифметика периодов написаны там второй раз намеренно - тогда числовое расхождение
с линиями Rust ingest/SQL является настоящей ошибкой, а не общим заблуждением.

`verify.ts` перегенерирует данные в два временных каталога и утверждает, что
(1) два прогона побайтово идентичны, (2) закоммиченные артефакты равны этому
выводу, (3) `expected.json` - стабильная редукция от него и (4) `out/facts.jsonl`
стабилен, совпадает с закоммиченным файлом и удовлетворяет контракту по полям и
порядку.
