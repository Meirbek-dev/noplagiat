# Обёртки диаграмм

Вся визуализация отрисовывается через обёртки в этом каталоге - маршруты никогда
не импортируют `@tanstack/charts` напрямую (AGENTS.md, соглашения по TS). Обёртки
берут цвета только из `src/styles/tokens.css`, локализованные строки - только из
сообщений paraglide, и поставляют описанный ниже каркас доступности.

| Компонент              | Раздел дашборда | Статус |
| ---------------------- | --------------- | ------ |
| `ScreenedValue`        | везде           | готово |
| `KpiCard`              | 1 обзор         | готово |
| `TimeSeries`           | 2, 9            | готово |
| `GroupedBars`          | 3 виды работ    | готово |
| `OriginalityHistogram` | 5 гистограмма   | готово |
| `UnitHeatmap`          | 4 подразделения | готово |
| `YoYCompare`           | 9 год к году    | готово |

## Типы пропсов локальны, и это намеренно

`types.ts` объявляет формы, которые принимают обёртки, - `ScreenedNumber`,
`TimeSeriesPoint`, `CategoryRow`, `OriginalityBucket`, `HeatmapRow`,
`HeatmapMetric`, `SparklinePoint`, `ChartSeries`. Они _зеркалят_ формы,
передаваемые по сети (`ScreenedNumber` - то же объединение
`number | "insufficient_data"`, которое объявляют сгенерированные
`ScreenedInt` / `ScreenedFloat` в `src/api/types.gen.ts`), но не импортируются из
`src/api/`, потому что этот каталог целиком перегенерируется из контракта
(инвариант #5 из AGENTS.md).

**Код маршрутов и страниц адаптирует сгенерированные типы API в эти пропсы.**
Загрузчик маршрута получает сгенерированный DTO, отображает его в
`TimeSeriesPoint[]` / `CategoryRow[]` / `HeatmapRow[]` - попутно разрешая
идентификаторы словарей в локализованные подписи, поскольку обёртки никогда не
ищут подписи сами, - и передаёт результат вниз. Когда появится генератор,
изменится только этот адаптер; слой диаграмм - нет.

Подписи, доходящие до обёртки, уже локализованы. Идентификаторы (`unit_id`,
`id` серии, `id` категории) непрозрачны и стабильны; цвет следует за
идентификатором, а не за рангом строки.

## Цвет

Каждое значение принадлежит `tokens.css`. Код диаграмм именует цвета только через
`format.ts`:

- `seriesColor(slot)` → `var(--chart-1..6)` - **категориальная идентичность**.
  Слоты назначаются в фиксированном порядке и никогда не переиспользуются по
  кругу; сверх шести серий вызывающий код сворачивает хвост в строку «Прочее»
  либо разбивает диаграмму на фасеты.
- `rampColor(step)` / `rampInk(step)` → `var(--chart-seq-1..5)` - **порядковая и
  последовательная величина** (корзины оригинальности, ячейки тепловой карты)
  плюс цвет текста, удерживающий подпись на этой ступени выше 4.5:1.
- `var(--chart-band)`, `var(--chart-ink)`, `var(--chart-ink-muted)`,
  `var(--suppressed-*)` - для оформления и для отображения подавленных значений.

`.np-chart` (тоже в `tokens.css`) переопубликовывает палитру как `--ts-chart-1..6`,
под именами, которые читает `@tanstack/charts`, поэтому даже метка без явно
заданной заливки попадает в проверенный фирменный цвет. `tokens.test.ts` роняет
сборку при появлении hex-литерала где угодно под `src/` за пределами `tokens.css`.

Палитра выведена и проверена методом `dataviz` (`validate_palette.js`) отдельно
для светлой и для тёмной поверхности; числа записаны в комментарии-заголовке
`tokens.css`.

## Подавление - единственный особый случай

`ScreenedNumber` со значением `"insufficient_data"` никогда не превращается в
ноль, в пропуск в таблице или в отсутствующую строку:

- в тексте - `ScreenedValue` (приглушённый чип «недостаточно данных»);
- на линии - точка становится `null`, поэтому линия _разрывается_, а не
  интерполирует тренд, который сервер отказался публиковать;
- в полосе столбчатой диаграммы, где рисовать больше нечего, - маркер печатается
  на базовой линии этой полосы;
- в ячейке тепловой карты - штриховой `<pattern>` из `SuppressedPatternDefs` плюс
  текст маркера;
- всегда - явное примечание под диаграммой с подсчётом изъятого и маркер в скрытой
  таблице данных.

`tokens.css` также предоставляет `.np-suppressed-hatch` - CSS-форму той же
штриховки для подавленных **областей** в обычном HTML, то есть для ячеек детализации
в TanStack Table из W2.4. `.np-suppressed` (плоский, без штриховки) - форма для
подавленного _текста_, чтобы сама фраза оставалась читаемой.

## Контракт доступности

`ChartFrame` даёт каждой обёртке: видимые заголовок и описание, текстовую легенду
(идентичность никогда не передаётся одним лишь цветом), примечание о подавлении и
визуально скрытую `<table>` со всеми точными значениями. Каждая область построения
дополнительно несёт доступное имя и описание, а также подсказку по каждой точке.

**Отступление от задания:** SVG-рендерер `@tanstack/charts` 0.16 выдаёт
`role="img" aria-label="…"` плюс `<desc>` и не имеет точки расширения для элемента
`<title>`. `aria-label` _и есть_ доступное имя SVG (и по SVG-AAM он в любом случае
имеет приоритет над `<title>`), поэтому диаграммы на базе библиотеки предоставляют
имя + `<desc>`; написанный вручную `UnitHeatmap` выдаёт настоящие `<title>` и
`<desc>`.

## Два намеренных отступления в оформлении

1. **`TimeSeries` по умолчанию использует `layout="stacked"`, а не двойную ось.**
   ARCHITECTURE §5.2 описывает линейную диаграмму с двумя осями (проверки /
   средняя оригинальность); руководство `dataviz` прямо запрещает две шкалы по y,
   потому что точка пересечения, которую читатель выносит из такой диаграммы,
   является артефактом выбора шкалы. Реализованы обе - `layout="dual-axis"`
   строит ровно ту диаграмму, которую описывает архитектура, со второй осью
   справа, - а по умолчанию используется двухпанельная форма. Переключите проп,
   если заказчик потребует двойную ось; больше ничего не меняется.
2. **У `GroupedBars` одна ось значений.** «Количество и среднее по виду работы» -
   это две единицы измерения, поэтому это две диаграммы `GroupedBars` рядом, по
   одной на меру, а не одна диаграмма со второй шкалой. `YoYCompare` - тот же
   компонент с учебным годом на оси категорий.

`UnitHeatmap` написан вручную как типизированный SVG, а не как метка `cell`: 0.16
принимает в качестве объявленных ресурсов диаграммы только _линейные градиенты_, а
отображение подавленных значений обязано быть SVG-`<pattern>`. Форма его обёртки,
токены, подсказки и поведение таблицы идентичны тем, что у диаграмм на базе
библиотеки.

## Тесты

`charts.test.tsx` отрисовывает каждую обёртку через `react-dom/server` - адаптер
диаграмм порождает свой SVG во время рендера React, поэтому настоящие метки, оси,
разрывы и каркас доступности целиком оказываются в выводе без эмулятора DOM.
Поведение после монтирования (наведение, фокус с клавиатуры, поверхность подсказки)
относится к слою Playwright в W2.7.
