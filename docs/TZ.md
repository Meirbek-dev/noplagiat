## 1. Общие сведения

### 1.1. Наименование системы

Панель аналитики по антиплагиату НАО «Торайгыров университет» - веб-раздел на портале университета `tou.edu.kz`, консолидирующий данные системы проверки на уникальность текста `noplagiat.tou.edu.kz`.

### 1.2. Основание для разработки

Разработка ведётся в рамках подготовки к выездному мониторингу Лиги Академической честности (ЛАЧ) и приведения университета в соответствие с Рубрикой институционализации академической честности (7 компонентов, 39 показателей). Система напрямую закрывает следующие показатели рубрики:

| Показатель                   | Компонент                          | Требование                                                                                |
| ---------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------- |
| Служба                       | Участие и поддержка преподавателей | Институциональная служба проверки на плагиат должна быть измеримой и системно применяемой |
| Соблюдение                   | Политики и процедуры               | Ведение агрегированной статистики нарушений за 2–3 года                                   |
| Доступность информации       | Политики и процедуры               | Структурированное и находимое размещение данных на сайте                                  |
| Прозрачность                 | Исследования и оценка              | Регулярная публикация обобщённой (обезличенной) статистики нарушений                      |
| Институциональное оценивание | Исследования и оценка              | Регулярный цикл количественной оценки в динамике                                          |

### 1.3. Термины и сокращения

## 2. Назначение и цели создания

**Назначение** - консолидировать данные о работе сервиса проверки на антиплагиат (`noplagiat.tou.edu.kz`) и представить их в виде наглядной, регулярно обновляемой аналитики для двух аудиторий: внешней (портал, ЛАЧ, коллектив) и внутренней (профильные подразделения университета).

**Цели:**

1. Обеспечить соответствие показателям Рубрики ЛАЧ, перечисленным в п. 1.2.
2. Предоставить руководству университета, деканатам и кафедрам инструмент мониторинга ситуации с академической честностью в динамике.
3. Повысить прозрачность процессов проверки письменных работ на уникальность перед коллективом и внешними проверяющими.
4. Снизить трудозатраты на ручную подготовку статистики для годовых отчётов (самоотчёт ЛАЧ, отчёт Совета по этике, отчёты по аккредитации) - в том числе автоматически формировать отчёт по форме Приложения 1 к приказу №13803.

## 3. Источники данных и интеграции

### 3.1. Основной источник данных

Система проверки на плагиат `noplagiat.tou.edu.kz`. Минимальный набор полей выгрузки:

| Поле                         | Тип          | Описание                                                                                                                    |
| ---------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| ID проверки                  | строка/число | Уникальный обезличенный идентификатор проверки работы                                                                       |
| Дата и время проверки        | дата/время   | Для построения динамики во времени                                                                                          |
| Тип работы                   | справочник   | Курсовая, ВКР (бакалавриат), магистерская диссертация, докторская диссертация (PhD), научная статья ППС, отчёт по НИР, иное |
| Факультет / институт         | справочник   | Для разбивки по подразделениям                                                                                              |
| Кафедра                      | справочник   | Для внутренней детализации                                                                                                  |
| ОП / специальность           | справочник   | Для внутренней детализации (опционально на публичном контуре)                                                               |
| Показатель оригинальности, % | число        | Итоговый процент уникальности текста                                                                                        |
| Статус проверки              | справочник   | Принято / направлено на доработку / отклонено / повторная проверка                                                          |
| Номер попытки проверки       | число        | Для отслеживания повторных проверок одной работы                                                                            |
| Признак эскалации            | булево       | Передано ли дело на рассмотрение в Совет/Комитет по этике                                                                   |
| Роль инициатора проверки     | справочник   | Студент, ППС (самопроверка), офис регистратора, иное                                                                        |

> **Персональные данные.** ФИО автора работы, ФИО проверяющего и полный текст работы **не передаются** в дашборд и **не хранятся** в его базе данных. Используется только обезличенный идентификатор проверки, необходимый для трассировки в исходной системе антиплагиата (см. раздел 6).

### 3.2. Дополнительные источники данных

- Справочники факультетов, кафедр, ОП - из портала / АРМ офиса регистратора (для единообразия наименований).
- Данные об общем количестве сданных работ по типам - для расчёта показателя охвата проверками (если доступны в системе учебного процесса).
- Реестр рассмотренных дел Совета по этике - агрегированные счётчики по категориям нарушений, без персональных данных.

### 3.3. Способ и периодичность интеграции

1. **Предпочтительный способ** - REST API системы `noplagiat.tou.edu.kz` с инкрементальной выгрузкой (по курсору `ID проверки` / дате).
2. **Резервный способ** - регулярная выгрузка CSV/Excel по расписанию (ежедневно, в ночное время; ответственный - Департамент цифрового развития и ИИ) с загрузкой через административный интерфейс или каталог импорта.
3. Периодичность обновления данных во внутреннем контуре - **не реже 1 раза в сутки**; сводные показатели публичного контура - **не реже 1 раза в квартал** (технически обновляются вместе с внутренними, публикация среза - по регламенту).
4. Загрузка обязана быть **идемпотентной**: повторная загрузка одного и того же периода не создаёт дублей (upsert по `ID проверки`).
5. Каждая загрузка фиксируется в журнале импорта (время, источник, число записей, ошибки валидации).

## 4. Функциональные требования

### 4.1. Общая архитектура контуров

Система состоит из двух контуров, объединённых общим бэкендом и разной логикой отображения:

- **Публичный контур** - открытая страница на портале `tou.edu.kz` в разделе «Академическая честность» (Комплаенс-служба); доступна без авторизации; отображает только агрегированные показатели общеуниверситетского уровня с применением правила k-анонимности (п. 6.2). Поддерживает встраивание (embed) на страницы портала.
- **Внутренний контур** - доступен через единый вход портала (SSO) авторизованным ролям (раздел 5); отображает детализацию по факультетам, кафедрам, ОП и типам работ.

### 4.2. Состав метрик и разделов дашборда

| №   | Раздел                                     | Содержание                                                                                                                                                                                                                                  | Контур                           |
| --- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| 1   | Обзорная сводка                            | Карточки KPI за выбранный период: всего проверок; средний показатель оригинальности; доля работ ниже порогового значения (порог настраиваемый, по умолчанию 70%); охват проверками (доля от общего числа сданных работ, при наличии данных) | Публичный + Внутренний           |
| 2   | Динамика во времени                        | Линейный график: количество проверок и средний показатель оригинальности по месяцам/семестрам за 3–5 лет                                                                                                                                    | Публичный + Внутренний           |
| 3   | Разбивка по типам работ                    | Столбчатая диаграмма: количество проверок и средняя оригинальность по типам (курсовые, ВКР, магистерские и докторские диссертации, статьи ППС, НИР, иное)                                                                                   | Публичный + Внутренний           |
| 4   | Разбивка по факультетам / кафедрам         | Таблица + тепловая карта: количество проверок и средняя оригинальность. Публичный контур - только уровень факультетов при соблюдении k-анонимности; внутренний - вплоть до кафедр и ОП                                                      | Внутренний (агрегат - публичный) |
| 5   | Распределение по диапазонам оригинальности | Гистограмма долей работ по диапазонам: <50%, 50–70%, 70–85%, 85–95%, ≥95%                                                                                                                                                                   | Публичный + Внутренний           |
| 6   | Повторные проверки                         | Доля работ, прошедших повторную проверку после доработки; из них доля с улучшенным показателем оригинальности                                                                                                                               | Внутренний                       |
| 7   | Эскалации                                  | Количество случаев, переданных в Совет/Комитет по этике, и статус рассмотрения (агрегированные счётчики, без персональных данных; без указания конкретных кафедр при малой выборке)                                                         | Внутренний (агрегат - публичный) |
| 8   | Использование системы                      | Количество активных пользователей (ППС, офис регистратора), среднее время выполнения проверки                                                                                                                                               | Внутренний                       |
| 9   | Год к году                                 | Сравнение ключевых показателей текущего периода с аналогичным периодом прошлых лет                                                                                                                                                          | Публичный + Внутренний           |

Все разделы визуализируются графически (карточки KPI со спарклайнами, линейные и столбчатые диаграммы, гистограммы, тепловые карты); таблицы применяются как дополнение к графике, а не вместо неё.

### 4.3. Фильтры

- **Период** - произвольный диапазон дат с быстрым выбором: месяц, семестр, учебный год, 3 года, 5 лет.
- **Факультет / институт**; на внутреннем контуре - дополнительно **кафедра** и **ОП**.
- **Тип работы.**
- **Статус проверки.**

Фильтры работают в любой комбинации; состояние фильтров кодируется в URL (для ссылок на конкретное представление и корректного экспорта).

### 4.4. Экспорт данных

- Выгрузка текущего представления (с учётом применённых фильтров) в **PDF** (для отчётов) и **Excel** (для дальнейшей обработки).
- Экспорт из публичного контура содержит только обезличенные агрегаты, прошедшие фильтр k-анонимности.
- Экспорт из внутреннего контура помечается «Для служебного пользования» и доступен только ролям с соответствующими правами; факт экспорта журналируется (п. 6.3).

### 4.5. Автоматическая подготовка отчётов

- Система автоматически формирует обезличенный отчёт по заданному шаблону, воспроизводящему структуру формы Приложения 1 к приказу №13803 (общие показатели; по типам работ; распределение по диапазонам; по факультетам; повторные проверки; эскалации; использование системы).
- Периодичность - не реже 1 раза в год (за учебный год: 1 сентября - 31 августа), с возможностью ручного запуска за произвольный период.
- Сформированные отчёты хранятся как неизменяемые снимки (дата формирования, период, файлы PDF/Excel) и доступны для публикации на портале.

### 4.6. Административные функции

- Настройка источников данных и расписаний обновления; ручной запуск импорта.
- Управление справочниками (факультеты, кафедры, ОП, типы работ) и их сопоставлением с наименованиями исходной системы.
- Настройка порогов: порог оригинальности (по умолчанию 70%), порог k-анонимности (по умолчанию k = 5).
- Управление ролями и областями видимости (факультет/кафедра); просмотр журнала доступа и журнала импорта.

## 6. Требования к защите персональных данных

### 6.1. Общие требования

Система должна соответствовать Закону Республики Казахстан «О персональных данных и их защите». В базе данных дашборда **не хранятся и не отображаются**: ФИО студентов и авторов работ; ФИО проверяющих (кроме служебных учётных записей администраторов, не выводимых в аналитику); полный текст проверяемых работ.

### 6.2. Правило k-анонимности

- На публичном контуре, а также в агрегированных представлениях внутреннего контура для широкой аудитории, показатель **не отображается** (заменяется отметкой «недостаточно данных»), если число наблюдений в агрегируемой группе за выбранный период меньше порогового значения k.
- Рекомендуемое значение k = 5; порог настраивается администратором.
- Правило применяется на уровне сервера (API): подавленные значения не передаются клиенту ни в каком виде, включая экспорт.

### 6.3. Журналирование доступа

Все обращения к внутреннему контуру (кто, когда, к какому разделу, с какими фильтрами, включая экспорт) журналируются; журнал хранится **не менее 1 года** и доступен администратору и Комплаенс-службе для аудита. Журнал ведётся в режиме «только добавление» (append-only).

## 8. Требования к пользовательскому интерфейсу

Оформление - по корпоративному брендбуку университета:

- основной цвет - тёмно-синий `#1D3D66`;
- акцентный цвет - оранжевый `#DE6E35`;
- логотип Toraighyrov University - в шапке публичной страницы и внутренней панели;
- типографика - шрифт без засечек, используемый на портале (Arial/аналог).

**Виджеты:** карточки KPI, линейные графики динамики, столбчатые диаграммы сравнения, гистограмма распределения, таблицы с фильтрами и сортировкой, тепловая карта по подразделениям. Приоритет - максимально графическое, визуальное представление данных.

**Embed:** публичный виджет поддерживает встраивание на отдельную страницу портала «Академическая честность» (iframe/веб-компонент с автоподстройкой высоты).

**Доступность:** контрастность текста и графики не ниже WCAG 2.1 AA; все графики дублируются текстовыми значениями (подписи/тултипы), состояние «недостаточно данных» отображается явно.

## 10. Критерии приёмки

1. Все метрики п. 4.2 отображаются корректно и соответствуют контрольным выгрузкам из исходной системы.
2. Фильтры (п. 4.3) работают корректно, в том числе в любых комбинациях.
3. Экспорт в PDF и Excel формирует корректные файлы с учётом применённых фильтров.
4. Правило k-анонимности (п. 6.2) проверено на тестовых данных: показатели с числом наблюдений менее порога не отображаются и не передаются в API/экспорте.
5. Ролевая модель (раздел 5) проверена: пользователь каждой роли видит только предусмотренные для него данные (проверка на уровне API, а не только интерфейса).
6. Журналирование доступа (п. 6.3) фиксирует все обращения к внутреннему контуру, включая экспорт.
7. Нагрузочное тестирование подтверждает требования раздела 7 (время загрузки ≤ 3 с при 50 000 записей; работоспособность при 250 000 записей).
8. Интерфейс соответствует брендбуку университета (раздел 8) и требованиям локализации.
9. Автоматическое формирование обезличенного отчёта (п. 4.5) проверено на реальном периоде данных; сформированы отчёты за 2024–2025 и 2025–2026 учебные годы по форме Приложения 1.
