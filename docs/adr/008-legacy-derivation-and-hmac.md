# ADR-008 - Правила вывода при бэкфилле легаси-данных, HMAC-референсы и общие константы

**Статус:** принято · 30.08.2026
**Закрывает:** D3 (HMAC `work_ref`/`reviewer_ref`), D6 (вывод статуса, политика «Удален»), D8 (границы семестров) из [PLAN.md](../PLAN.md) §2.
**Контекст:** в легаси-выгрузках вендора за 2021–2026 годы, лежащих в `stats/`, отсутствует большинство полей TZ §3.1; их приходится выводить. Несколько лейнов (fixtures, ingest, db, reports) реализуют эти правила независимо, а их результаты сравниваются побитово, поэтому каждое правило зафиксировано здесь один раз. Этот ADR расширяет инвариант #1 (никаких ПДн): ничто именное или обратимое не сохраняется.

## 1. Диалект исходного CSV (`documents.csv`)

- UTF-8 **с BOM**; разделитель `;`; кавычки по RFC-4180 (поля могут содержать `;` и встроенные переводы строк); десятичная **запятая** в числовых полях; даты `dd.MM.yyyy HH:mm`.
- Наивные временные метки интерпретируются как фиксированное смещение **+05:00** для всех лет (задокументированное приближение; месячная гранулярность его поглощает).
- Контракт заголовка - ровно эти 14 колонок, в этом порядке (при любом несовпадении партия отвергается целиком):

```
Дата загрузки документа;Название документа;Авторы;Оригинальность;Самоцитирование;Цитирование;Совпадение;Проверяющий;Email проверяющего;Подозрительный документ;Отметка о подозрительности снята;Статус;Ссылка на полный отчет;ИИ-контент
```

- Булевы значения: «Да» → true, что угодно другое (включая пустое, «Нет») → false, без учёта регистра, с обрезкой пробелов.
- Одиночное тире (`-`/`–`/`-`) в **необязательной** метрической колонке (Самоцитирование, Цитирование, Совпадение, ИИ-контент) означает «нет значения» → NULL; наблюдалось в реальных выгрузках 2021/22–2024/25 при бэкфилле W4.3 («ИИ-контент» равен `-` во всех строках, предшествующих появлению ИИ-детектора). Тире в «Оригинальность» остаётся основанием для отбраковки.
- `Статус` несёт «Не удален» / «Удален».
- Ссылка на отчёт `…/report/full/{reportId}?userId={userId}` → `source_check_id = "{userId}:{reportId}"`. Неудалённая строка без разбираемой ссылки - **типизированная отбраковка** (значение никогда не угадывается). Удалённая строка учитывается отдельно (см. §4).

`system-usage.csv` (одна агрегатная строка на год) импортируется в `source_control_totals` исключительно для сверки W4.3. `user-intensity.csv` **никогда не импортируется** (содержит ФИО; не добавляет сигнала - помесячное число активных проверяющих выводится из `reviewer_ref`).

## 2. HMAC-референсы (D3 - утверждено)

- Пеппер (pepper): переменная окружения `APP_INGEST_PEPPER` (обязательна в режиме CSV; никогда в БД, никогда в Git, никогда в логах).
- Нормализация `norm(s)`: Unicode NFC → обрезка пробелов → схлопывание внутренних последовательностей пробелов в один пробел → приведение к нижнему регистру.
- `work_ref  = HMAC-SHA256(pepper, "work\n"     ++ norm(Название документа) ++ "\n" ++ norm(Авторы))` (32-байтовый BYTEA).
- `reviewer_ref = HMAC-SHA256(pepper, "reviewer\n" ++ norm(Email проверяющего))` (32-байтовый BYTEA).
- Открытые название, авторы, имя и e-mail проверяющего отбрасываются внутри функции разбора и никогда не сохраняются и не логируются.
- `staff_units.masked_label`: первый символ локальной части e-mail + `***` + последние 4 символа локальной части (просто `first char + "***"`, если локальная часть короче 6) + `@` + полный домен. Пример: `z***v.vn@teachers.tou.edu.kz`.

## 3. Группировка попыток

В пределах одного `work_ref` строки упорядочиваются по `(checked_at, source_check_id)` по возрастанию; `attempt_no` - порядковый номер, начиная с 1. Применяется только к CSV-бэкфиллу - новая исходная система поставляет `attempt_no` нативно (контракт W1.0).

## 4. Вывод статуса (D6 - значения по умолчанию, редактируемые администратором через `settings.status_rules`)

Удалённые строки (`Статус = «Удален»`) **исключаются** из аналитических фактов при `settings.exclude_deleted = true` (по умолчанию), но учитываются в `ingest_batches.rows_skipped_deleted`.

Для остальных строк выигрывает первое совпадение:

1. `attempt_no > 1` → `recheck`
2. `Подозрительный = Да AND Отметка снята ≠ Да` → `rejected`
3. `originality < settings.originality_threshold` (по умолчанию 70) → `needs_revision`
4. иначе → `accepted`

`escalated = (Подозрительный = Да AND Отметка снята ≠ Да)` - независимо от лестницы статусов.

## 5. Правила инициатора (значения по умолчанию, редактируемые администратором через `initiator_rules`)

Сопоставляются с (никогда не сохраняемым) e-mail проверяющего во время разбора, по приоритету:

1. домен `teachers.tou.edu.kz` → `staff_self`
2. локальная часть начинается с `registrar` или `reg.` → `registrar`
3. иначе → `other`

## 6. Привязка к подразделению

`staff_units(email_hmac → faculty, department)` разрешает проверяющего в подразделение. Непривязанные проверяющие → строки-заглушки словарей `UNASSIGNED`/«Не распределено» (и факультет, **и** кафедра). Годы до 2025/26 структурно относятся к «Не распределено» (PLAN §1.2) - интерфейс несёт сноску «Разбивка по подразделениям доступна с 2025/26 уч. года».

## 7. Классификация типов работ

`work_type_rules(pattern, work_type_id, priority, active)` - сопоставление подстроки/регулярного выражения без учёта регистра с (никогда не сохраняемым) нормализованным названием; выигрывает первое совпадение по приоритету; нет совпадения → `other`/«иное».

## 8. Семестры (D8) и периоды

- Осенний: **1 сентября – 31 января**; весенний: **1 февраля – 31 августа** (лето отнесено к весеннему). Хранится в `settings.semester_boundaries`.
- Учебный год: 1 сентября – 31 августа; `AcademicYear(2024)` = 2024/25 уч. год.
- Корзины гистограммы (нижняя граница включительно): `<50, [50,70), [70,85), [85,95), ≥95`.

## 9. Определения метрик разделов

- **Сводка**: `checks` = число строк; `avg_originality` (среднее, 4 знака после запятой, округление половин вверх в фикстурах); `below_threshold_share` = доля строк с `originality < originality_threshold`; `coverage` = checks÷`submission_totals` (скрывается при отсутствии знаменателей).
- **Повторные проверки** (§4.2 §6): по строкам, попадающим под фильтр, группировка по `work_ref`: `works_total` = число различных работ; `works_rechecked` = работы с ≥ 2 попытками в отфильтрованном множестве; `improved` = перепроверенные работы, у которых оригинальность последней попытки > оригинальности первой попытки.
- **Эскалации**: число фактов с `escalated`; счётчики Комиссии по этике берутся из `ethics_cases` (вручную, D11) и приводятся отдельно.
- **Использование**: помесячное число различных `reviewer_ref`; `avg_check_seconds` - только из ручных записей `usage_stats` (иначе «нет данных»).

## 10. Общие имена интерфейсов

- CLI ингеста CSV: `cargo run --manifest-path server/Cargo.toml --bin ingest-csv -- --dir <dir>` (ожидает `documents.csv`, опционально `system-usage.csv`; также принимает `--documents <file>`; `--source <label>`, по умолчанию `csv-backfill`). Читает `APP_DATABASE_URL`, `APP_INGEST_PEPPER`.
- Генератор фикстур: `bun fixtures/generate.ts --scale small|load` → `fixtures/out/<ay>/documents.csv` (плюс словари и правила в SQL/CSV); полнопереборный редьюсер `bun fixtures/expected.ts` → `fixtures/expected.json` (сырые, **до подавления** агрегаты плюс размеры групп, так что подавление проверяется отдельно тестами `compliance`).

## Последствия

- Фикстуры, ингест, SQL и отчёты реализуют эти правила по одному этому тексту; числовое расхождение - ошибка в одном из них, а не вопрос к спецификации.
- Все значения по умолчанию редактируемы в рантайме (настройки / таблицы правил); этот ADR фиксирует только сами значения по умолчанию и семантику вывода.
- Если Комплаенс впоследствии оспорит правило (R5), изменение будет правкой настроек плюс повторным ингестом, а не изменением схемы.
