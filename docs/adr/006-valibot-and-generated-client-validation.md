# ADR-006: Valibot и валидация в сгенерированном клиенте

**Статус:** принято · 2026-08-30

**Контекст:** TZ.md §9 требует Valibot для валидации на фронтенде, тогда как
первоначальный каркас использовал Zod и `@tanstack/zod-adapter` для параметров
поиска дашборда и стартового API-клиента. TanStack Router поддерживает схемы
Valibot 1.x напрямую через Standard Schema, поэтому отдельный адаптер для роутера
не требуется. ADR-003 дополнительно требует, чтобы TypeScript-клиент генерировался
из OpenAPI-контракта, произведённого Rust.

**Решение:** параметры поиска, формы и границы API-ответов на фронтенде используют
Valibot. Опции маршрутов `validateSearch` получают схемы Valibot напрямую.
Будущий этап генерации OpenAPI-клиента обязан выпускать runtime-схемы Valibot и
использовать их для валидации неизвестных данных ответа; он не должен возвращать
Zod или рукописные типы ответов. Реализация этого генератора остаётся отдельным
изменением контрактного лейна, координируемым на корне репозитория.

Инструментарий, относящийся только к фронтенду, классифицируется как
предназначенный только для разработки: CLI shadcn и пакеты devtools TanStack живут
в `devDependencies`, а Vite-плагин devtools включается только в режиме разработки.
Прямые зависимости TanStack, которые были указаны как `latest`, закреплены на
версиях, уже зафиксированных в lock-файле, чтобы установки не расходились
независимо друг от друга.

**Последствия:** в приложении один словарь runtime-валидации, соответствующий
нормативному стеку, удалён Zod-адаптер роутера, и CLI/devtools-зависимости не
поставляются как production-требования. Генерация OpenAPI не считается
завершённой, пока сгенерированный клиент не включает схемы Valibot и проверку на
расхождение; до тех пор существующий стартовый клиент остаётся временным.

**Реализация (W2.2, 30.08.2026).** `vp run gen:api` экспортирует контракт
и запускает `@hey-api/openapi-ts` в `apps/web/src/api/`; `vp run gen:api:check`
перегенерирует во временный каталог и сравнивает результат, и выполняется во
фронтенд-джобе CI. Валидация _не_ генерируется в SDK (`validator: false`):
обёртка `fetchScreened` в `src/lib/api.ts` разбирает каждый ответ по
сгенерированной схеме Valibot, когда активен `import.meta.env.DEV` или тестовый
режим, и доверяет серверу в production-сборках - то самое разделение по
окружениям, которого требует этот ADR, выраженное в одном месте, а не в каждой
операции. Разбор - только проверка; сгенерированный TypeScript-тип остаётся
авторитетным, поэтому успешный разбор никогда не переформирует значение.
Поскольку `Screened<i64>` - это объединение `int64` и маркера подавления, а
плагин Valibot рендерит `int64` как приведение к `BigInt`, которое проглатывает
строку маркера, конфигурация генератора убирает `format: int64` - по проводу
передаются JSON-числа, а сгенерированный TypeScript уже говорит `number`.
