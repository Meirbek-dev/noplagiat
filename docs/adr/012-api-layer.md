# ADR-012 - Слой API: топология middleware, сессии и страж k-анонимности

**Статус:** принято · 30.08.2026
**Слайсы:** W1.6 (топология слоёв и каркас аутентификации), W2.1 (публичные эндпоинты)
**Контекст:** [ARCHITECTURE.md §4.2–§4.3, §4.6, §6](../ARCHITECTURE.md) · [TZ.md §4.2–§4.3, §5, §6](../TZ.md) · [ADR-002](002-typed-k-anonymity.md) · [ADR-008 §8–§9](008-legacy-derivation-and-hmac.md)

Крейт `api` был каркасом из трёх маршрутов. Этот ADR фиксирует решения, принятые при превращении его в настоящий HTTP-край: какие слои существуют, в каком порядке, где живут сессии и как гарантия k-анонимности обеспечивается на уровне передаваемых данных, а не ревью.

---

## 1. Топология слоёв (как реализовано)

Каждый контур получает **собственный** стек. Не разделяется ничего, кроме трассировочного span и заполнителя `instance` из RFC 7807, потому что слой, смонтированный не на тот контур, - это ровно тот способ, которым обходится комплаенс-контроль. Снаружи внутрь:

```
/healthz, /readyz   → (no layers)

/api/public/*       → TraceLayer → problem-instance → security headers (public CSP)
                      → RateLimit(per-IP) → Cache-Control + ETag → KAnonymityGuard

/api/internal/*     → TraceLayer → problem-instance → security headers (private CSP)
                      → SessionAuth → RequireInternalAccess → RequireSectionRole
                      → CSRF → AuditLayer

/api/admin/*        → the internal stack + RequireRole(admin), between
                      RequireInternalAccess and CSRF

/api/auth/*         → TraceLayer → problem-instance → security headers
                      (+ SessionAuth and CSRF on /me and /logout only)
```

Обоснование порядка:

- **RequireInternalAccess перед AuditLayer.** Ответ 403 - не просмотр раздела; его журналирование заполнило бы `audit_log` не-событиями и исказило бы TZ §6.3. `RequireSectionRole` (`api::rbac`, добавлен вместе с сужением эскалаций из ADR-014 §7) находится в том же окне, на один слот позже, - на той позиции, которую на административном контуре занимает `RequireRole(admin)`.
- **CSRF после SessionAuth.** Токен сравнивается со строкой сессии, поэтому сессию нужно загрузить первой.
- **ETag снаружи стража.** Дайджест должен считаться ровно от тех байт, которые получает клиент, а страж срезает свой маркер на выходе.
- **RateLimit снаружи слоя кеширования.** Ограниченный запрос должен стоить одного поиска по хешу, а не обращения к базе данных.

## 2. `KAnonymityGuard`: что здесь означает «сильнейшая практически осуществимая проверка»

Первичное подавление уже является типом: поле публичного DTO - это `compliance::Screened<T>`, и вне `compliance` не существует конструктора, превращающего сырой агрегат в такое значение (ADR-002). Два режима отказа это переживают:

1. **новый обработчик** под `/api/public`, который вообще ничего не экранировал;
2. обработчик, выполнивший экранирование относительно **неверного `n`** - `Screened<T>` не помнит размер группы, из которой он был создан, поэтому система типов этого не увидит.

Страж закрывает оба. Каждый публичный обработчик возвращает `Guarded<T>`, который несёт `KAnonWitness`: действующее `k` плюс, для каждой публикуемой метрики, **JSON-указатель** на неё и число наблюдений, стоящих за ней.

| Сборка       | Проверка                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| release      | свидетельство (или маркер `x-kanon-checked`) присутствует; при его отсутствии ⇒ `500` + лог `error!`, тело не отдаётся                                                                                                                                                                                                                                                                                                      |
| debug и test | дополнительно обходится сериализованное тело: (а) каждый засвидетельствованный указатель обязан разрешаться - свидетельство, разошедшееся с DTO, ничего не доказывает; (б) каждый указатель, чья группа содержит `n < k`, обязан разрешаться в `"insufficient_data"`; (в) ни одно число под ключом, похожим на метрику (`checks`, `avg_originality`, `escalated`, `share`, …), не может остаться не покрытым свидетельством |

Обратная импликация намеренно **не** проверяется: ячейка с `n ≥ k` вполне может быть подавлена законно, поскольку комплементарное подавление скрывает большие ячейки ради защиты малых.

Почему не «обойти JSON и сравнить с размерами групп, приложенными к ответу»? Потому что ответ не несёт размеров групп - публикация точного `n` рядом с каждой подавленной ячейкой сама была бы утечкой. Свидетельство - та же информация, но переданная **вне полосы**, и именно это делает проверку возможной вообще.

Маркер - внутреннее утверждение и никогда не является частью контракта: страж удаляет и расширение, и заголовок до того, как ответ покинет процесс, а тест проверяет, что `x-kanon-checked` отсутствует в каждом публичном ответе.

## 3. Сессии живут в `api` - пока что

Миграция `0004_sessions.sql` добавляет одну таблицу: `sessions(id BYTEA PK, user_id FK, created_at, expires_at, csrf_token BYTEA)`, оба blob'а под `CHECK (octet_length(...) = 32)`. Идентификатор - 32 байта из CSPRNG операционной системы, закодированные в hex в cookie `np_session` (`HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age`). Ничто не подписывается, и в cookie не переносится ничего, кроме идентификатора: каждое решение об авторизации - это чтение из базы данных, поэтому отзыв роли или деактивация пользователя вступают в силу на **следующем запросе**, а не при следующем входе (интеграционный тест проверяет и то, и другое).

Четыре SQL-выражения для сессий живут в `api::auth::store`, а не в `db`. Сессии - забота HTTP-края, которая пришла вместе с этим слайсом, пока лейн `db` был закрыт; это макросы `sqlx::query!`, проверяемые на этапе компиляции, как и любое другое выражение в рабочем пространстве (AGENTS.md §5), и это единственный SQL, которым владеет `api`. **Когда лейн `db` снова откроется, этот модуль без изменений переедет в `db::sessions`.**

`csrf_token` хранится отдельно для каждой сессии, а не выводится из идентификатора, поэтому утечка одного не даёт другого.

## 4. Схлопывание области видимости в RBAC

`CurrentUser.roles` (список выдач `(role, faculty?, department?)`) схлопывается в один `compliance::Scope`, побеждает самая широкая: `All > Faculty > Department`, ничьи разрешаются по наименьшему id подразделения.

Два решения, которые стоит зафиксировать:

- **`db::users` документирует NULL-область как «весь университет».** Это прочтение применяется только к `ethics`, `compliance` и `admin` - трём ролям, которым TZ §5 даёт общеуниверситетский доступ. Для `dean` или `dept_head` NULL-область - это наполовину заполненная административная форма, и безопасное прочтение «нет подразделения» означает _отсутствие данных_, а никак не _все подразделения_.
- **`staff` не даёт внутренней области видимости.** TZ §5 даёт ППС публичный контур плюс, опционально, собственные агрегаты; такого представления пока не существует, поэтому учётная запись только с ролью staff получает `403` на `/api/internal/*`.

**TODO(W3.2):** `Scope` содержит одно подразделение, поэтому пользователь, которому выданы два факультета, сейчас видит тот, у которого номер меньше. Слайс с RBAC-матрицей либо расширит `Scope` до множества, либо запретит такую выдачу.

## 5. Ограничение частоты запросов: самописное, а не `tower_governor`

Токен-бакет на каждый IP (`burst`, `per_minute`, по умолчанию 120 / 600) за `Mutex<HashMap<IpAddr, _>>`, с очисткой при превышении таблицей 8192 записей. `tower_governor` был отклонён: он добавляет дерево зависимостей (`governor`, `nonzero_ext`, `quanta`, `no-std-compat`) ради примерно сорока строк арифметики, а его API квот затрудняет внедрение часов - в данной же реализации есть `check_at(client, Instant)`, которым модульные тесты управляют без ожидания.

Лимит намеренно щедрый. Публичные ответы отдаются с `Cache-Control: public, max-age=3600`, поэтому легитимный посетитель портала делает один запрос на раздел в час; бакет существует, чтобы притупить скрейпинг, а не чтобы формировать нормальный трафик.

Адрес клиента: первый переход из `X-Forwarded-For`, выставляемого шлюзом, затем `X-Real-IP`, затем адрес пира сокета. ARCHITECTURE.md §8 держит порт Rust приватным за nginx, поэтому проброшенный заголовок так же надёжен, как и сокет; прямой запрос такого заголовка не имеет и попадает на `ConnectInfo`.

## 6. `AuditLayer` пишет синхронно, а не из порождённой задачи

ARCHITECTURE.md §4.2 набрасывала вариант со spawn. Строка - это одна индексированная вставка по соединению, которое запрос уже держит, и запись до возврата ответа даёт две вещи, которых spawn дать не может:

- приёмочное доказательство для TZ §10.6 - это тест, читающий строку сразу после ответа: без опроса, без флаки;
- неудачная запись аудита наблюдаема. Ответ всё равно уходит (отказ обслуживать из-за сбоя логирования - неверный компромисс для дашборда), но она логируется на уровне `error` и будет питать метрику «отказы записи аудита» из слайса W4.5.

`filters` - это нормализованная строка запроса: percent-декодированная, с отброшенными пустыми значениями и **отсортированными ключами**, - так что одно и то же представление журналируется одинаково независимо от того, в каком порядке клиент передал параметры. `section` - это путь совпавшего маршрута с удалённым префиксом контура (`/api/internal/ping` → `ping`).

`section` сохраняет **шаблон** маршрута со всеми плейсхолдерами: административный запрос словаря журналируется как `dictionaries/{kind}`, а не `dictionaries/faculties`. Именно это удерживает словарь разделов ограниченным множеством, которое административный браузер может предложить как элемент управления фильтром, - по той же причине кардинальности, которую §8 ADR-014 приводит для метки метрики. При этом плейсхолдер остаётся неразрешённым, а TZ §6.3 требует журналировать «с какими фильтрами» - _какой именно_ словарь и есть ровно это, - поэтому разрешённые параметры маршрута сливаются в `filters` рядом с ключами запроса (`{"kind": "faculties", "q": "FAC"}`). Они читаются через `axum::extract::RawPathParams`, которому нужны части запроса, а не заимствование, поэтому слой разбирает запрос и тут же собирает его обратно. Параметры маршрута побеждают одноимённый ключ запроса; ни один маршрут в этом крейте не имеет плейсхолдера, конфликтующего с именем фильтра, и ни один не несёт ничего, кроме кода или непрозрачного идентификатора (инвариант #1 в AGENTS.md).

## 7. Контракт публичных запросов

Имена на проводе следуют ARCHITECTURE.md §4.6 и `apps/web/src/lib/search.ts`: `?period&from&to&faculty&work_type&status`, где `period ∈ {month, semester, year, 3y, 5y, custom}`, а значение по умолчанию - `year` (= учебный год). Отсчётная дата для относительных пресетов - сегодняшний день в фиксированном университетском гражданском календаре **+05:00** (ADR-008 §1), а границы семестров берутся из `settings.semester_boundaries`, поэтому выбор «семестр» следует ADR-008 §8 без передеплоя.

Три решения:

- **`deny_unknown_fields`.** `department`, `program` и `initiator` отклоняются с `422`, называющим параметр. TZ §4.2 §4 помещает гранулярность кафедры на внутренний контур, поэтому публичный запрос, требующий её, должен получить отказ, а не быть молча расширен. (`work_type` пишется на проводе в snake*case; `search.ts` называет тот же фильтр `workType` в URL *страницы\_, а сгенерированный клиент выполняет отображение между ними в W2.2.)
- **Каждое поле объявлено как `Option<String>` и валидируется через `garde`.** Десериализация сразу в перечисления даёт `serde` возможность упасть первым, и его сообщение называет вариант, но не поле; валидация строк даёт каждому отказу путь до поля. Собственное сообщение `serde` `unknown field \`x\`` по той же причине разбирается обратно в имя поля.
- **Пресет, отличный от `custom`, побеждает переданную пару `from`/`to`** (обе всё равно валидируются). Отклонение сохранённого в закладках `?period=year&from=…` было бы враждебно пользователю дашборда, всё состояние фильтров которого живёт в URL; описание параметра прямо об этом говорит.

## 8. RFC 7807 повсеместно

Один документ `Problem` - `type`, `title`, `status`, `detail`, `instance` плюс массив `errors[]` из `{field, message}` на 422 - с медиатипом `application/problem+json`, на каждом ответе, отличном от 2xx, включая запасные 404 и 405 самого роутера. `type` - относительный URI (`/problems/validation-failed`, …), поэтому контракт не несёт имени хоста.

`instance` заполняется одним слоем, который пересериализует любое тело problem с путём запроса, вместо того чтобы протаскивать его через каждую точку вызова. Это же покрывает problem, порождённые внутри экстракторов и слоёв, у которых нет чистого доступа к пути.

## 9. Заголовки безопасности

Оба контура: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`.

Они различаются ровно в одном - можно ли помещать ответ во фрейм:

- **публичный:** `Content-Security-Policy: default-src 'none'; frame-ancestors <origins>`, без `X-Frame-Options` (он перекрыл бы CSP). TZ §8 требует, чтобы публичный виджет загружался в iframe портала.
- **внутренний / административный / auth:** `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `Cache-Control: no-store`.

### Закрепление origin (W2.5, выполнено)

Публичный контур был выпущен с `frame-ancestors *` и пометкой, что слайс **W2.5** закрепит origin портала. Он это сделал: список источников теперь - `AppConfig::embed_frame_ancestors`, читаемый один раз при старте из **`APP_EMBED_FRAME_ANCESTORS`** и по умолчанию равный `api::layers::security::DEFAULT_FRAME_ANCESTORS`:

```
'self' https://tou.edu.kz https://www.tou.edu.kz
```

`'self'` сохраняет возможность фреймить собственный маршрут `/embed` дашборда им же самим; два хоста портала - это origin, названные в TZ §8. Три решения:

- **Конфигурируется, а не компилируется внутрь.** Второй хост портала, staging-origin или репетиция против preview-домена - это изменение окружения, а не релиз; то же рассуждение ADR-008 §8 применяет к порогам. Значение читается в бинарнике, а не на каждый запрос, поэтому политика, публикуемая деплоем, не может измениться посреди работы процесса.
- **Построение заголовка тотально.** `unwrap`/`expect` запрещены clippy в `api`, а опечатка оператора не должна ни ронять процесс, ни, хуже того, публиковать политику, которой никто не писал. Значение, которое пусто, содержит `;` (что позволило бы протащить вторую директиву CSP мимо списка origin) или не является допустимым значением заголовка, откатывается к приведённому выше значению по умолчанию с `tracing::warn!`. Пути от плохого значения к `*` не существует.
- **Документы остаются за шлюзом.** `deploy/nginx.conf` задаёт CSP для SSR-маршрута `/embed` и для оболочки приложения; данная переменная управляет **только ответами API**, и именно поэтому значению по умолчанию и списку шлюза позволено быть записанными в двух местах, а не в одном, - они защищают разные ресурсы, и файл шлюза принадлежит другому лейну.

`tests/layers.rs` проверяет, что значение по умолчанию появляется в публичном ответе, что сконфигурированный список соблюдается и что непригодный откатывается, - всё это управляется через `AppConfig`, а не мутацией окружения процесса, которое разделяют остальные тесты в этом бинарнике.

## 10. Режимы аутентификации

> **Замещено [ADR-017](017-local-accounts.md).** Режимов больше нет: `APP_AUTH_MODE`, `POST /api/auth/dev-login` и поток OIDC удалены, вход выполняется по логину и паролю из таблицы `users`. Раздел сохранён как запись о том, что было решено на момент W1.6.

`APP_AUTH_MODE` принимал значения `oidc` (по умолчанию) или `dev`; незаданное или написанное с ошибкой значение было **отказом при старте**, а не молчаливым откатом, поскольку эти два режима различались наличием `dev-login`.

- `oidc`: `GET /api/auth/login` отвечал `503` с указанием слайса **W3.1**, а `POST /api/auth/dev-login` отвечал `404` - в продакшене этого маршрута не существовало.
- `dev`: `POST /api/auth/dev-login` создавал сессию напрямую (PLAN.md D7, R3). Это был единственный изменяющий состояние эндпоинт вне CSRF-слоя, потому что именно этот запрос _создавал_ токен. Он не принимал ни имени, ни e-mail - поля синтетической учётной записи выводились из непрозрачного subject, - поэтому его нельзя было использовать, чтобы поместить имя человека в базу данных (инвариант #1 в AGENTS.md). Ту же роль теперь играет `POST /api/auth/login`: он вне CSRF-слоя по той же причине и принимает только логин и пароль.

**Сознательно не добавлены:**

- **`tower_governor`** - см. §5.
- **`axum-extra` / `tower-cookies`** - cookie представляет собой одно непрозрачное hex-значение с четырьмя фиксированными атрибутами. Её чтение - это `split(';')` по заголовку `Cookie`, а запись - `format!`; обе занимают меньше двадцати строк с модульными тестами, против зависимости, чью связанность с версией axum пришлось бы отслеживать.
- **`percent-encoding`** - слою аудита нужно декодирование `application/x-www-form-urlencoded` ради одной колонки; декодер занимает пятнадцать строк с собственными тестами (AGENTS.md §5: предпочитать std и уже присутствующие крейты).

## Последствия

- Новый публичный эндпоинт, забывший про экранирование, проваливает собственный прогон тестов - в страже, до ревью.
- `contracts/openapi.json` теперь описывает шестнадцать путей и тридцать схем, причём `Screened<T>` отображается как `oneOf [T, SuppressedMarker]` - сгенерированный в W2.2 фронтенд-клиент получает объединение с подавлением в своих типах, а не голое число.
- Хранилище сессий находится в «неправильном» крейте, пока лейн `db` его не перенесёт; ничто за пределами двух модулей `api` не зависит от того, где оно живёт.
- `Scope` остаётся одноединичным; выдача нескольких факультетов - открытый вопрос для W3.2.
