# ADR-009: Раздельные контейнеры Rust API и Node SSR за одним шлюзом nginx

**Статус:** принято · 2026-08-30

## Контекст

TanStack Start собирает бандл серверного рендеринга, который должен исполняться в
JavaScript-рантайме. Прежний деплой собирал только бинарник Rust и PostgreSQL, тогда как
архитектура утверждала, что Rust отдаёт и статические файлы, и SSR. Ни SSR-адаптера для
Rust, ни встроенного фронтенд-артефакта не существовало, поэтому такая топология не могла
обслуживать задокументированное приложение.

Публичное, внутреннее и встраиваемое представления должны разделять один origin с Rust API
ради cookie, OIDC-колбэков и браузерных запросов. Rust и Node не должны быть выставлены как
независимые публичные сервисы. Кроме того, каркас Compose использовал бета-образ
PostgreSQL 19, который не годится для разворачиваемой базовой конфигурации.

## Решение

Разворачиваются четыре сервиса с раздельной ответственностью:

1. `gateway`: nginx - единственный HTTP-вход. Он маршрутизирует `/api`, `/api/*`, `/healthz`,
   `/readyz` и `/metrics` на Rust, а все остальные пути - на веб-сервис.
2. `web`: процесс Node.js отдаёт `dist/client/` и стримит сгенерированный обработчик
   TanStack Start Fetch из `dist/server/server.js`. Адаптер без зависимостей в
   `deploy/web-server.mjs` предоставляет границу Node HTTP, поскольку текущий результат
   сборки - Fetch-обработчик, а не самостоятельно слушающий исполняемый файл.
3. `server`: бинарник Rust/Axum владеет API, эндпоинтами health/readiness, миграциями
   и внутрипроцессной фоновой работой.
4. `postgres`: PostgreSQL использует стабильную мажорную линию `18-alpine` в приватной сети
   данных. Продакшен-манифесты релиза дополнительно закрепляют проверенные дайджесты образов.

Образ web собирается многостадийно: Bun устанавливает закоммиченный lock-файл и запускает
существующую сборку фронтенда; образ рантайма Node получает только production-зависимости,
результат сборки и адаптер. Это решение о деплое не требует изменений ни во фронтенд-пакете,
ни в исходном коде приложения.

nginx сохраняет внешние хост и протокол, проброшенные университетским прокси, и использует
непосредственно наблюдаемые им значения как запасной вариант для локальной разработки.
Адаптер Node вправе доверять нормализованным заголовкам nginx только потому, что его порт
приватен для сети Compose; входящий трафик на продакшен-шлюз ограничен университетским
прокси. Базовый адрес API на фронтенде остаётся незаданным, поэтому браузерные запросы
используют маршрут `/api` того же origin. TLS по-прежнему терминируется на университетском
обратном прокси, который пробрасывает трафик на nginx.

## Последствия

- У SSR теперь есть реальный рантайм, и он может стримить ответы независимо от релизов Rust.
- API, колбэки аутентификации, страницы и ассеты разделяют один браузерный origin без
  настройки CORS и без публичных URL внутренних сервисов.
- Rust, Node и PostgreSQL не публикуются на портах хоста; nginx - единственная граница
  HTTP-маршрутизации и доверия внутри стека.
- Деплой собирает и эксплуатирует один дополнительный образ приложения и один образ шлюза.
  Логи и здоровье приходится инспектировать по каждому сервису отдельно.
- `/healthz` и `/readyz` сообщают о здоровье Rust. Compose отдельно проверяет, что Node
  принимает TCP-соединения. `/metrics` зарезервирован, но остаётся недоступным, пока не
  реализован обработчик метрик в Rust.
- Теги Compose закрепляют мажорную/минорную линии рантаймов ради воспроизводимости
  намерения, но остаются изменяемыми. Продвижение в продакшен обязано разрешать и
  фиксировать неизменяемые проверенные дайджесты.
- Закоммиченный пример окружения содержит только плейсхолдеры. Секреты базы данных и
  будущие секреты OIDC должны приходить из хранилища секретов деплоя.

## Отклонённые альтернативы

- **Rust отдаёт фронтенд и SSR:** отклонено, поскольку не существует ни JavaScript-рантайма
  для SSR, ни адаптера для Rust, а одна лишь отдача статики молча превратила бы требуемое
  SSR-приложение в SPA.
- **Статический SPA, отдаваемый nginx или Rust:** отклонено, поскольку SSR на TanStack Start -
  нормативное требование проекта и часть стратегии производительности.
- **Выставить Rust и Node напрямую:** отклонено, поскольку это создаёт несколько публичных
  origin, усложняет безопасные cookie/OIDC и позволяет клиентам обойти границу доверия прокси.
- **Запустить nginx и Node в одном контейнере:** отклонено, поскольку это связывает жизненный
  цикл процессов, здоровье и масштабирование, не давая никакого выигрыша по сравнению с
  небольшим сервисом-шлюзом.
