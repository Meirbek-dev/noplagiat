# ADR-020: Закрепление совместимой цепочки компилятора Paraglide

**Статус:** принято · 2026-09-09

## Контекст

После обновления зависимостей сборка web падает на импорте переводов:
`@inlang/paraglide-js@2.25.1` → `@inlang/sdk@3.0.4` → `@lix-js/sdk@0.15.1`.
Ошибка воспроизводится в журнале контейнерной сборки и локально под Node.
Откат транзакции сообщает `No Lix transaction is active`, скрывая исходную
ошибку фиксации Lix: `native field count differs between rows`.

## Решение

Закрепить `@inlang/paraglide-js` на `2.25.0`, а `@inlang/sdk` — на `3.0.3`
через корневой `overrides`. Это восстанавливает цепочку с `@lix-js/sdk@0.12.3`
из lock-файла до обновления. Одного закрепления Paraglide недостаточно:
его диапазон `^3.0.1` допускает проблемный SDK `3.0.4`.
Новых зависимостей нет; `bun.lock` перегенерируется менеджером пакетов.

## Последствия

Компиляция настоящих каталогов RU/KK/EN и сборка клиента/SSR снова проходят.
Переводы и сгенерированные файлы не требуют ручных изменений.
Закрепление снимается отдельным обновлением после успешной компиляции этих
каталогов, тестов локализации и сборки образа web с новым SDK.
